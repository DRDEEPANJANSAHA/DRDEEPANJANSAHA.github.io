Egress Allowlist Bypass on Tool Paths

Agentic & Tool Layer · L3 · MCP + tool calls

The egress allowlist governs the tools — not the tools' tools: a permitted dependency can resolve to a new host, a fetch can follow redirects past the list, and a base64 payload can exit inside an 'allowed' API call. The allowlist and the actual byte path diverge, and the gap is the lane.

01Control Architecture

How it is defended

Egress control follows bytes, not intent: redirect and DNS resolution are checked against the allowlist at the socket layer, payloads in allowed channels are scanned (the L5 exfil battery), and new-host appearance is a canary test. An allowlist that governs intent but not bytes is decoration.

03FAQ

How do agents exfiltrate past an egress allowlist?
