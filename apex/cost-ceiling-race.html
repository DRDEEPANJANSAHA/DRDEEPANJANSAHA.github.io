Cost-Ceiling Races in Concurrent Agent Systems

Evals & Economics · L5 · guardrails + cost

Concurrent agents sharing a cost pool have a race: check-then-act on the budget isn't atomic, and N agents each 'see' headroom that no longer exists by the time they act. The overshoot is a DoS on your own infrastructure — your agents, racing, blowing the ceiling you set for them.

01Control Architecture

How it is defended

Budget accounting is transactional: atomic check-and-reserve on the cost pool, per-agent reservations that the pool actually backs, and an audit that reconciles reservations against actual spend. The race is a design property you remove, not a threshold you tune — the gate treats an unreconciled pool as a defect.

03FAQ

What is a cost-ceiling race in concurrent agents?

Multiple agents check the shared budget, all see headroom, all act — the pool is exhausted before any one reservation. The fix is atomic check-and-reserve with reconciled accounting: the budget is a transaction, not a peek, and the gate audits that it stays one.

How do you defend against cost-ceiling races in concurrent agent systems?
